# Travel-Collab

**Travel-Collab** — full-stack приложение для совместного планирования путешествий. Сервис помогает группе путешественников создать поездку, пригласить участников, спланировать маршруты по дням, отметить точки на карте, вести общий чат и учитывать расходы между участниками.

Проект разработан как выпускная квалификационная работа по направлению **09.03.04 «Программная инженерия»** и демонстрирует полный цикл создания информационной системы: backend, frontend, база данных, real-time взаимодействие, мобильная версия и Android-приложение.

---

## Возможности

### Поездки и участники

- регистрация и вход по email и паролю;
- создание поездок;
- подключение участников по invite-коду;
- роли участников поездки: владелец и редактор;
- разграничение доступа к данным поездки.

### Карта и маршруты

- интерактивная карта на базе Leaflet и OpenStreetMap;
- добавление точек поездки на карту;
- категории точек: достопримечательность, еда, отель, транспорт, другое;
- создание маршрутов по дням;
- ручной порядок точек маршрута;
- drag-and-drop для изменения последовательности точек;
- построение линии маршрута между точками;
- открытие маршрута во внешнем сервисе 2ГИС.

### Расходы и взаиморасчёты

- добавление расходов по поездке, маршруту или конкретной точке;
- несколько плательщиков в одном расходе;
- распределение суммы между участниками поровну или вручную;
- проверка корректности сумм оплат и долей;
- финансовая сводка по участникам;
- расчёт итоговых балансов;
- список «кто кому должен» для упрощения взаиморасчётов.

### Совместная работа

- чат внутри поездки;
- WebSocket-обновления без перезагрузки страницы;
- синхронизация изменений между участниками поездки;
- поддержка одновременной работы нескольких пользователей.

### Web и mobile

- адаптивный web-интерфейс для ПК и мобильного браузера;
- Android-приложение на базе Capacitor;
- единый backend для web-версии и мобильного приложения;
- возможность использовать сервис с телефона во время самой поездки.

## Технологический стек

### Backend

- **Go** — серверная часть приложения;
- **Chi** — HTTP-маршрутизация;
- **PostgreSQL** — основная реляционная база данных;
- **PostGIS** — хранение и обработка географических координат;
- **JWT** — аутентификация пользователей;
- **WebSocket** — обновления в реальном времени;
- **Docker Compose** — локальный запуск инфраструктуры.

### Frontend

- **Vue 3** — клиентская часть приложения;
- **TypeScript** — типизация frontend-кода;
- **Vite** — сборка и dev-сервер;
- **Leaflet** — интерактивная карта;
- **Capacitor** — сборка Android-приложения на основе web-клиента.

## Архитектура

Проект построен по клиент-серверной архитектуре.

```text
Пользователь
   │
   ├── Web-клиент Vue / TypeScript
   │        │
   │        ├── REST API
   │        └── WebSocket
   │
   ├── Android-приложение Capacitor
   │        │
   │        ├── REST API
   │        └── WebSocket
   │
   └── Backend Go
            │
            └── PostgreSQL + PostGIS
```

Backend отвечает за бизнес-логику, безопасность, работу с базой данных, маршруты API и WebSocket-события. Frontend отвечает за пользовательский интерфейс, карту, формы, отображение маршрутов, расходов и чата. Android-приложение использует тот же frontend-код и тот же backend, что и web-версия.

## Локальный запуск

### Требования

- Go;
- Node.js и npm;
- Docker Desktop;
- Git;
- для Android-сборки: Android Studio и Android SDK.

### Запуск web-версии

Основной способ запуска проекта в режиме разработки:

```powershell
cd C:\Users\valer\GolandProjects\travel-collab
.\scripts\dev.ps1
```

Скрипт поднимает PostgreSQL/PostGIS через Docker Compose, запускает backend, frontend и открывает приложение в браузере.

После запуска web-версия доступна на ПК:

```text
http://localhost:5173
```

Если телефон находится в той же локальной сети, web-версию можно открыть в мобильном браузере по IP компьютера:

```text
http://<IP_компьютера>:5173
```

Например:

```text
http://192.168.1.166:5173
```

## Android-приложение

Android-версия собирается через Capacitor и использует тот же интерфейс, что и web-клиент.

Подробная инструкция по сборке и установке APK находится в файле:

```text
frontend/MOBILE.md
```

Общий сценарий работы:

1. запустить backend на компьютере;
2. собрать Android APK с указанием IP компьютера;
3. установить APK на телефон;
4. открыть приложение и войти в аккаунт.

Пример команды сборки:

```powershell
cd frontend
powershell -ExecutionPolicy Bypass -File .\scripts\mobile-build.ps1 -BackendHost 192.168.1.166
```

APK создаётся в каталоге:

```text
frontend/android/app/build/outputs/apk/debug/app-debug.apk
```

## Тестирование и безопасность

В проект добавлена документация для проверки основных сценариев и описания механизмов защиты.

```text
docs/testing.md      # сценарии функционального и автоматизированного тестирования
docs/security.md     # описание механизмов безопасности
docs/deploy.md       # инструкция production-развертывания
docs/ci.md           # описание GitHub Actions CI
docs/traceability.md # трассировка требований: требование → код → проверка
```

Тестирование включает проверку регистрации, входа, создания поездок, маршрутов, точек, расходов, drag-and-drop, WebSocket-чата, мобильной web-версии и Android-приложения.

Для критической бизнес-логики расходов добавлены модульные тесты backend: проверяется корректность оплат, распределения сумм и расчёта взаиморасчётов между участниками. Также добавлены тесты production/security-helper-ов: CORS/Origin, WebSocket Origin-check, проверка слабого JWT-секрета и rate limiting для авторизации.

Локальная проверка запускается командой:

```powershell
.\scripts\test.ps1
```

Для быстрой повторной проверки без переустановки frontend-зависимостей:

```powershell
.\scripts\test.ps1 -SkipFrontendInstall
```

На GitHub добавлен workflow `.github/workflows/ci.yml`, который выполняет `go test ./...` для backend и `npm run build` для frontend.

## Безопасность

В текущей версии реализованы базовые механизмы защиты:

- хранение паролей в хешированном виде;
- JWT-аутентификация;
- защита API через middleware;
- проверка доступа пользователя к поездке;
- разграничение действий по ролям участников;
- защита WebSocket-подключения через токен;
- хранение секретов в переменных окружения.

Для публичной демонстрации добавлены production-настройки: отдельный `docker-compose.prod.yml`, Caddy reverse proxy, строгий CORS для production, WebSocket Origin-check, запрет слабого JWT-секрета в production, rate limiting на регистрацию/вход и ограничение размера входящих запросов. Для полноценной промышленной эксплуатации систему все еще нужно дополнить refresh-токенами, журналированием действий пользователей, постоянным мониторингом и расширенной политикой резервного копирования.
