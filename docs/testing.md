# План тестирования Travel-Collab

Тестирование проекта выполняется в трех формах:

1. автоматизированные модульные тесты backend для критической бизнес-логики расходов, конфигурации production-режима, CORS/WebSocket Origin и rate limiting;
2. автоматизированная проверка сборки frontend;
3. ручное функциональное тестирование пользовательских сценариев web-версии, мобильной web-версии и Android APK.

## Автоматизированные проверки

Команда запуска из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1
```

Если зависимости frontend уже установлены и нужно быстро перепроверить только backend-тесты и сборку, можно использовать:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1 -SkipFrontendInstall
```

Скрипт выполняет:

- `go test ./...` в `backend/`;
- `npm ci` в `frontend/`, если не передан флаг `-SkipFrontendInstall`;
- `npm run build` в `frontend/`.

Backend-тесты покрывают:

- распределение суммы расхода поровну с учетом копеек;
- проверку итогов оплат и долей в копейках, а не через неточные float-сравнения;
- обнаружение повторяющихся участников в оплатах и долях;
- нормализацию optional ID для связи расхода с маршрутом или точкой;
- расчет упрощенных переводов “кто кому должен”;
- игнорирование околонулевых балансов при взаиморасчетах;
- fallback-логику для старых расходов с одним `paid_by`;
- нормализацию production/development-конфигурации;
- запрет локальных Origin в production-режиме;
- разрешение локальных Origin в development-режиме;
- проверку слабого JWT-секрета;
- WebSocket Origin check;
- rate limiting для чувствительных endpoint-ов авторизации.

## CI на GitHub

Для репозитория добавлен workflow `.github/workflows/ci.yml`. Он запускается при push, pull request и вручную через `workflow_dispatch`.

CI выполняет два независимых job-а:

| Job | Проверка | Назначение |
|---|---|---|
| Backend Go tests | `go test ./...` | Проверяет backend-логику, тесты расходов и security-helper-ы |
| Frontend build | `npm ci` и `npm run build` | Проверяет, что Vue/TypeScript frontend собирается без ошибок |


## Условия ручного тестирования

- ОС: Windows 10/11;
- база данных: PostgreSQL + PostGIS через Docker Compose;
- backend: Go;
- frontend: Vue/Vite;
- браузер ПК: Chrome/Edge;
- мобильный браузер: Chrome/Safari;
- Android APK: debug-сборка Capacitor;
- телефон и компьютер находятся в одной локальной сети либо используют публичный backend после деплоя.

## Ручные сценарии

| № | Сценарий | Действия | Ожидаемый результат |
|---|----------|----------|---------------------|
| 1 | Регистрация | Открыть frontend, перейти к регистрации, заполнить email, имя и пароль | Пользователь создан, выполнен вход, открыт список поездок |
| 2 | Вход | Выйти из системы и войти по email/паролю | JWT сохранен, пользователь попадает в `/trips` |
| 3 | Создание поездки | Создать поездку с названием и описанием | Поездка появилась в списке, текущий пользователь стал владельцем |
| 4 | Invite-код | Скопировать invite-код поездки | Код копируется, его можно использовать другим пользователем |
| 5 | Вступление в поездку | Вторым пользователем ввести invite-код | Второй пользователь добавлен как участник поездки |
| 6 | Создание маршрута | На вкладке карты создать маршрут с названием и датой | Маршрут появился в списке маршрутов |
| 7 | Добавление точки | Выбрать маршрут, кликнуть по карте, заполнить форму точки | Точка появляется на карте и в списке маршрута |
| 8 | Редактирование точки | Изменить название, категорию или время точки | Точка обновляется на карте и во вкладке маршрута |
| 9 | Drag-and-drop точек | Перетащить точку в списке маршрута выше/ниже | Порядок сохраняется, линия маршрута перестраивается |
| 10 | 2ГИС | Нажать кнопку открытия маршрута в 2ГИС | Открывается внешний маршрут по точкам в заданном порядке |
| 11 | Добавление расхода | Создать расход с одним плательщиком и распределением поровну | Расход добавлен, итоги пересчитаны |
| 12 | Несколько плательщиков | Создать расход, где оплатили несколько участников | Балансы считаются как “оплатил минус его доля” |
| 13 | Ручное распределение | Ввести суммы долей вручную | Расход сохраняется, если сумма долей равна общей сумме |
| 14 | Ошибка распределения | Ввести сумму долей, не равную общей сумме расхода | Появляется понятная ошибка с общей суммой, суммой долей и разницей |
| 15 | Детализация долгов | Нажать на баланс участника | Открывается детализация, кому и сколько он должен или кто должен ему |
| 16 | Чат | Отправить сообщение в чате | Сообщение появляется в списке и сохраняется |
| 17 | WebSocket | Открыть одну поездку в двух клиентах и добавить точку/сообщение | Второй клиент получает обновление без перезагрузки |
| 18 | Мобильный web | Открыть `http://IP_КОМПЬЮТЕРА:5173` на телефоне | Интерфейс открывается, вход и основные разделы работают |
| 19 | Android APK | Установить debug APK и войти в аккаунт | Приложение открывается и подключается к backend по IP компьютера или публичному URL |
| 20 | Health-check | Открыть `/api/v1/health` | Backend возвращает `status: ok` |
| 21 | Production compose | Запустить `scripts/prod-up.ps1` | Frontend, backend, PostgreSQL/PostGIS и reverse proxy поднимаются в Docker |
| 22 | Production WebSocket | Открыть чат через production reverse proxy | Сообщения передаются через тот же публичный origin |

## Негативные сценарии

| № | Сценарий | Ожидаемый результат |
|---|----------|---------------------|
| 1 | Вход с неверным паролем | Пользователь получает ошибку входа |
| 2 | Запрос к защищенному API без JWT | Backend возвращает 401 |
| 3 | Попытка открыть чужую поездку | Backend возвращает 403 или данные не отображаются |
| 4 | Расход с нулевой суммой | Форма/сервер отклоняют расход |
| 5 | Расход без плательщика | Отображается ошибка “Укажите, кто и сколько оплатил” |
| 6 | Расход без участников деления | Отображается ошибка “Укажите, между кем делится расход” |
| 7 | Расход с суммой оплат, не равной общей сумме | Backend возвращает ошибку с деталями суммы и разницы |
| 8 | Расход с суммой долей, не равной общей сумме | Backend возвращает ошибку с деталями суммы и разницы |
| 9 | Расход с повторяющимся плательщиком | Backend отклоняет расход |
| 10 | Расход с повторяющимся участником деления | Backend отклоняет расход |
| 11 | Маршрут в 2ГИС с одной точкой | Пользователь получает предупреждение, что нужно минимум две точки |
| 12 | Неизвестный Origin в production WebSocket | Подключение отклоняется Origin-check-ом |
| 13 | Частые запросы на login/register | Backend возвращает 429 Too Many Requests |
| 14 | Отключение backend | Frontend показывает ошибку запроса или потерю соединения |
