# План тестирования Travel-Collab

Тестирование проекта выполняется в двух формах:

1. автоматизированные модульные тесты для критической бизнес-логики расходов;
2. ручное функциональное тестирование пользовательских сценариев web-версии, мобильной web-версии и Android APK.

## Автоматизированные проверки

Команда запуска из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1
```

Скрипт выполняет:

- `go test ./...` в `backend/`;
- `npm install` и `npm run build` в `frontend/`.

Backend-тесты покрывают:

- распределение суммы расхода поровну с учётом копеек;
- проверку итогов оплат и долей;
- обнаружение повторяющихся участников в оплатах и долях;
- расчёт упрощённых переводов “кто кому должен”;
- fallback-логику для старых расходов с одним `paid_by`.

## Условия ручного тестирования

- ОС: Windows 10/11;
- база данных: PostgreSQL + PostGIS через Docker Compose;
- backend: Go;
- frontend: Vue/Vite;
- браузер ПК: Chrome/Edge;
- мобильный браузер: Chrome/Safari;
- Android APK: debug-сборка Capacitor;
- телефон и компьютер находятся в одной локальной сети.

## Ручные сценарии

| № | Сценарий | Действия | Ожидаемый результат |
|---|----------|----------|---------------------|
| 1 | Регистрация | Открыть frontend, перейти к регистрации, заполнить email, имя и пароль | Пользователь создан, выполнен вход, открыт список поездок |
| 2 | Вход | Выйти из системы и войти по email/паролю | JWT сохранён, пользователь попадает в `/trips` |
| 3 | Создание поездки | Создать поездку с названием и описанием | Поездка появилась в списке, текущий пользователь стал владельцем |
| 4 | Invite-код | Скопировать invite-код поездки | Код копируется, его можно использовать другим пользователем |
| 5 | Вступление в поездку | Вторым пользователем ввести invite-код | Второй пользователь добавлен как участник поездки |
| 6 | Создание маршрута | На вкладке карты создать маршрут с названием и датой | Маршрут появился в списке маршрутов |
| 7 | Добавление точки | Выбрать маршрут, кликнуть по карте, заполнить форму точки | Точка появляется на карте и в списке маршрута |
| 8 | Редактирование точки | Изменить название, категорию или время точки | Точка обновляется на карте и во вкладке маршрута |
| 9 | Drag-and-drop точек | Перетащить точку в списке маршрута выше/ниже | Порядок сохраняется, линия маршрута перестраивается |
| 10 | 2ГИС | Нажать кнопку открытия маршрута в 2ГИС | Открывается внешний маршрут по точкам в заданном порядке |
| 11 | Добавление расхода | Создать расход с одним плательщиком и распределением поровну | Расход добавлен, итоги пересчитаны |
| 12 | Несколько плательщиков | Создать расход, где оплатили несколько участников | Балансы считаются как “оплатил минус его доля” |
| 13 | Ручное распределение | Ввести суммы долей вручную | Расход сохраняется, если сумма долей равна общей сумме |
| 14 | Ошибка распределения | Ввести сумму долей, не равную общей сумме расхода | Появляется понятная ошибка с общей суммой, суммой долей и разницей |
| 15 | Детализация долгов | Нажать на баланс участника | Открывается детализация, кому и сколько он должен или кто должен ему |
| 16 | Чат | Отправить сообщение в чате | Сообщение появляется в списке и сохраняется |
| 17 | WebSocket | Открыть одну поездку в двух клиентах и добавить точку/сообщение | Второй клиент получает обновление без перезагрузки |
| 18 | Мобильный web | Открыть `http://IP_КОМПЬЮТЕРА:5173` на телефоне | Интерфейс открывается, вход и основные разделы работают |
| 19 | Android APK | Установить debug APK и войти в аккаунт | Приложение открывается и подключается к backend по IP компьютера |
| 20 | Health-check | Открыть `/api/v1/health` | Backend возвращает `status: ok` |

## Негативные сценарии

| № | Сценарий | Ожидаемый результат |
|---|----------|---------------------|
| 1 | Вход с неверным паролем | Пользователь получает ошибку входа |
| 2 | Запрос к защищённому API без JWT | Backend возвращает 401 |
| 3 | Попытка открыть чужую поездку | Backend возвращает 403 или данные не отображаются |
| 4 | Расход с нулевой суммой | Форма/сервер отклоняют расход |
| 5 | Расход без плательщика | Отображается ошибка “Укажите, кто и сколько оплатил” |
| 6 | Расход без участников деления | Отображается ошибка “Укажите, между кем делится расход” |
| 7 | Маршрут в 2ГИС с одной точкой | Пользователь получает предупреждение, что нужно минимум две точки |
| 8 | Отключение backend | Frontend показывает ошибку запроса или потерю соединения |

## Что использовать в дипломе

В главе тестирования можно указать, что проверка системы включала:

- модульное тестирование алгоритмов расчёта расходов;
- функциональное тестирование пользовательских сценариев;
- проверку real-time синхронизации через WebSocket;
- проверку адаптивной web-версии на телефоне;
- проверку Android APK, собранного через Capacitor;
- проверку обработки ошибок при некорректных данных.
